# Sub-Plan 2: Database Schema for Documents

✅ **Simple** — 可一次執行，低風險

## Overview

建立 `documents` 和 `chunks` 兩張新表（含 pgvector 向量欄位），移除 `conversations.openai_response_id` 欄位，加上 RLS 策略、IVFFlat 索引，並建立 `match_chunks` SQL 函數供向量相似度搜索使用。

## Step-by-Step Tasks

### Task 2.1 — 建立 Migration SQL

```sql
-- supabase/migrations/002_add_documents_and_chunks.sql

-- 1. Enable pgvector extension (idempotent)
CREATE EXTENSION IF NOT EXISTS vector;

-- 2. Remove openai_response_id from conversations
ALTER TABLE conversations DROP COLUMN IF EXISTS openai_response_id;

-- 3. Create documents table
CREATE TABLE documents (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  filename TEXT NOT NULL,
  file_type TEXT NOT NULL,          -- 'txt', 'md' (pdf/docx added in Module 5)
  file_size INTEGER NOT NULL,       -- bytes
  status TEXT NOT NULL DEFAULT 'pending'
    CHECK (status IN ('pending', 'processing', 'complete', 'error')),
  error_msg TEXT,
  chunk_count INTEGER DEFAULT 0,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 4. Create chunks table
CREATE TABLE chunks (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  document_id UUID NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
  user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  content TEXT NOT NULL,
  chunk_index INTEGER NOT NULL,
  token_count INTEGER NOT NULL,
  embedding vector(1536),           -- text-embedding-3-small dimension
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 5. Auto-update updated_at on documents
CREATE OR REPLACE FUNCTION update_documents_updated_at()
RETURNS TRIGGER AS $$
BEGIN
  NEW.updated_at = now();
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER documents_updated_at
  BEFORE UPDATE ON documents
  FOR EACH ROW EXECUTE FUNCTION update_documents_updated_at();

-- 6. Performance indexes
CREATE INDEX idx_documents_user_id ON documents(user_id);
CREATE INDEX idx_documents_status ON documents(status);
CREATE INDEX idx_chunks_document_id ON chunks(document_id);
CREATE INDEX idx_chunks_user_id ON chunks(user_id);

-- 7. IVFFlat index for approximate nearest neighbor search
--    lists=100 is appropriate for up to ~1M vectors; adjust for larger datasets
CREATE INDEX idx_chunks_embedding ON chunks
  USING ivfflat (embedding vector_cosine_ops)
  WITH (lists = 100);

-- 8. Row-Level Security: documents
ALTER TABLE documents ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Users can view own documents"
  ON documents FOR SELECT
  USING (auth.uid() = user_id);

CREATE POLICY "Users can insert own documents"
  ON documents FOR INSERT
  WITH CHECK (auth.uid() = user_id);

CREATE POLICY "Users can update own documents"
  ON documents FOR UPDATE
  USING (auth.uid() = user_id);

CREATE POLICY "Users can delete own documents"
  ON documents FOR DELETE
  USING (auth.uid() = user_id);

-- 9. Row-Level Security: chunks
ALTER TABLE chunks ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Users can view own chunks"
  ON chunks FOR SELECT
  USING (auth.uid() = user_id);

CREATE POLICY "Users can insert own chunks"
  ON chunks FOR INSERT
  WITH CHECK (auth.uid() = user_id);

CREATE POLICY "Users can delete own chunks"
  ON chunks FOR DELETE
  USING (auth.uid() = user_id);

-- 10. match_chunks: vector similarity search function
--     Called via supabase.rpc("match_chunks", {...})
--     Security definer so it can bypass RLS but uses user_id filter explicitly
CREATE OR REPLACE FUNCTION match_chunks(
  query_embedding vector(1536),
  match_user_id UUID,
  match_count INT DEFAULT 5,
  match_threshold FLOAT DEFAULT 0.7
)
RETURNS TABLE (
  id UUID,
  document_id UUID,
  content TEXT,
  chunk_index INT,
  similarity FLOAT
)
LANGUAGE plpgsql
SECURITY DEFINER
AS $$
BEGIN
  RETURN QUERY
  SELECT
    chunks.id,
    chunks.document_id,
    chunks.content,
    chunks.chunk_index,
    1 - (chunks.embedding <=> query_embedding) AS similarity
  FROM chunks
  WHERE
    chunks.user_id = match_user_id
    AND chunks.embedding IS NOT NULL
    AND 1 - (chunks.embedding <=> query_embedding) > match_threshold
  ORDER BY chunks.embedding <=> query_embedding
  LIMIT match_count;
END;
$$;
```

**關於向量維度：**
- `text-embedding-3-small` → 1536 維
- `text-embedding-3-large` → 3072 維
- Ollama `nomic-embed-text` → 768 維
- 如需支援不同維度，需在 migration 中用參數化或在 Module 5 處理

## Notes

- IVFFlat 索引在插入資料後需要重建才能生效（`REINDEX INDEX idx_chunks_embedding`），但對於 Module 2 的小數據量，exact scan 也可接受
- 若 embedding 模型維度不是 1536，需調整 `vector(1536)` 和 `match_chunks` 函數的參數型別
- CASCADE delete：刪除 document 時，其 chunks 自動刪除
